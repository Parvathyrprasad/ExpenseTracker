\# AI Permissions and Approval Policy



\## Approval Mode



\*\*Mode: Ask Before Making Changes\*\*



The AI coding assistant may inspect project files, explain code, suggest improvements, and identify potential issues. However, it must ask for my approval before making changes to the project.



\## Permissions



\- \*\*Read files:\*\* Allowed for understanding the existing project.

\- \*\*Suggest code changes:\*\* Allowed.

\- \*\*Edit existing files:\*\* Requires my approval.

\- \*\*Create new files:\*\* Requires my approval.

\- \*\*Install dependencies:\*\* Requires my approval.

\- \*\*Database schema changes and migrations:\*\* Require my approval.

\- \*\*Delete files or folders:\*\* Requires my approval.

\- \*\*Git commits and pushes:\*\* Require my approval.

\- \*\*Run tests and builds:\*\* Allowed for verification.



\## Security Rules



1\. Never expose passwords, API keys, tokens, or database credentials.

2\. Never overwrite or delete project files without approval.

3\. Never make database changes without explaining their impact.

4\. Never install new packages without approval.

5\. Never commit or push changes without approval.



\## Reason for This Approval Mode



I selected the ask-before-making-changes mode to maintain control over my project and understand every modification. It helps prevent accidental changes, protects sensitive information, and allows me to review AI-generated code before accepting it.



I remain responsible for reviewing, testing, and approving all changes before submission.
