\# AI Reflection — ExpenseTracker



Working on the ExpenseTracker project with AI assistance helped me understand how AI can support software development beyond simply generating code.



During this project, I used AI to understand the existing project structure, troubleshoot form validation issues, run backend and frontend tests, and prepare development documentation. I also created an `AGENTS.md` file to define project rules and coding standards, along with reusable skills for feature development and code review.



One important lesson I learned is that AI-generated suggestions should not be accepted without verification. Sometimes the suggested solution needs adjustments to work with the existing project and development environment. For example, I encountered difficulties configuring the pre-commit hook on Windows. I tested the scripts manually and confirmed that all 51 backend and frontend tests passed, although automatic Git hook execution still needs verification.



I also learned the importance of writing clear instructions, following a structured workflow, reviewing code changes, and running tests after modifications. The permissions policy helped me establish boundaries so that AI suggestions do not automatically result in changes to important project files.



Overall, this experience improved my understanding of AI-assisted development, debugging, testing, documentation, and responsible use of coding assistants. I learned that AI is a helpful development partner, but the developer remains responsible for understanding, reviewing, and verifying the final work.
